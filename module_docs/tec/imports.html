tec.imports

Find the imports of python code, using the standard library’s ast.

This module answers the question “what does this code import?” by parsing the code into an abstract syntax tree and walking it – so, unlike the regex-based tec.import_counting, it is not fooled by import-looking strings, comments, or line continuations.

The simple thing is simple:

>>> [imp.name for imp in imports_in_code("import os\nfrom json import dumps")]
['os', 'json.dumps']

The interface has three levels, from most to least specific:

  • imports_in_code(): imports of a string of python code

  • find_imports(): imports of a single .py file

  • imports_under_folder() / count_imports(): imports of every .py file under a folder – reached through the PyFilesReader store, so a “folder” can also be a module object, a package, or the path of an __init__.py file

ModuleImports offers the same information as a Mapping from module dotpath to the imports of that module.

Note: this module replaces the vendored copy of the (GPL-2.0-or-later) third party findimports project that tec used to ship as tec.findimports. It is an independent implementation, written against the standard library, so that tec can be distributed under its own Apache-2.0 terms.

tec.imports.ABSOLUTE_IMPORT_LEVEL = 0

Value of ImportInfo.level for an absolute (non-relative) import.

tec.imports.CODE_STRING_FILENAME = '<string>'

Placeholder used as the filename of imports parsed from a code string.

tec.imports.DFLT_IMPORT_KEY(imp: ImportInfo | str) → str

Default aggregation key of count_imports(): the top-level package name.

tec.imports.DFLT_ON_PARSE_ERROR(error: SyntaxError, path: str) → None

Default reaction to a file that can’t be parsed while walking a folder. Folders of real-world code routinely contain a stray py2 (or templated) file, so the default is to warn and move on instead of aborting the whole walk.

tec.imports.DFLT_PATH_FILT = None

None, i.e. no filtering beyond the store’s own restriction to .py files.

Type:

Default file-path predicate

tec.imports.FOREIGN_PATH_SEP = None

Path separator that is legal but not native on this platform ('/' on Windows, None elsewhere). File stores are not required to use the native one.

class tec.imports.ImportInfo(name: str, filename: str = '<string>', lineno: int = 0, level: int = 0)[source]

A single imported name, along with where it was found.

>>> imp = ImportInfo("os.path", "a.py", 3)

class tec.imports.ModuleImports(src: Any, *, root_module_str: str = '')[source]

Mapping from module dotpath to the tuple of imports of that module.

Parameters:

  • src – Anything PyFilesReader accepts: a folder path, a module or package object, or the path of an __init__.py file.

  • root_module_str – Prefix to give the module dotpaths (the keys).

Note: the dotpath-to-file index is computed once, lazily, on first use – files added to the folder afterwards will not show up in an existing instance.

>>> import tempfile
>>> from pathlib import Path
>>> with tempfile.TemporaryDirectory() as root:
...     _ = Path(root, '__init__.py').write_text('')
...     _ = Path(root, 'a.py').write_text('import os\nfrom json import dumps\n')
...     s = ModuleImports(root, root_module_str='pkg')
...     keys, n = sorted(s), len(s)
...     names = [imp.name for imp in s['pkg.a']]
>>> keys
['pkg.__init__', 'pkg.a']
>>> n
2
>>> names
['os', 'json.dumps']
tec.imports.base_package_of(imp: ImportInfo | str) → str[source]

The top-level package name of an import ('' for relative imports).

>>> base_package_of("collections.abc")
'collections'
>>> base_package_of(ImportInfo("os.path"))
'os'

A relative import has no resolvable top-level package, so it maps to '':

>>> base_package_of(ImportInfo("sibling", level=1))
''
tec.imports.count_imports(src: ~typing.Any, *, path_filt: ~collections.abc.Callable[[str], bool] | None = None, import_key: ~collections.abc.Callable[[~tec.imports.ImportInfo], ~typing.Any] = <function base_package_of>, on_parse_error: ~collections.abc.Callable[[SyntaxError, str], None] = <function warn_of_parse_error>) → Counter[source]

Count the imports of every .py file under src.

Parameters:

  • src – Anything PyFilesReader accepts (see imports_under_folder()).

  • path_filt – Optional predicate on the store’s (relative) file paths.

  • import_key – What to count: applied to each ImportInfo, it returns the value that is tallied. Defaults to base_package_of(), i.e. the top-level package name.

  • on_parse_error – See imports_under_folder().

Returns:

A collections.Counter.

>>> import tempfile
>>> from pathlib import Path
>>> with tempfile.TemporaryDirectory() as root:
...     _ = Path(root, 'a.py').write_text('import os\nfrom os import path\n')
...     _ = Path(root, 'b.py').write_text('import os.path\nimport json\n')
...     counts = count_imports(root)
...     full = count_imports(root, import_key=lambda imp: imp.name)
>>> sorted(counts.items())
[('json', 1), ('os', 3)]
>>> sorted(full.items())
[('json', 1), ('os', 1), ('os.path', 2)]

tec.imports.imports_in_code(code: str, *, filename: str = '<string>') → Iterator[ImportInfo][source]

Generate the ImportInfo of every import found in code.

Parameters:

  • code – The python source to parse.

  • filename – What to record as the origin of the imports found.

Returns:

A generator of ImportInfo.

>>> code = '''
... import os, sys
... import os.path as osp
... from collections.abc import Mapping
... from . import sibling
... from ..pkg import thing
... '''
>>> [imp.name for imp in imports_in_code(code)]
['os', 'sys', 'os.path', 'collections.abc.Mapping', 'sibling', 'pkg.thing']

Unlike a regex-based scan, text that merely looks like an import is ignored:

>>> list(imports_in_code('x = "import antigravity"  # import antigravity'))
[]

Imports nested in functions, classes, try blocks etc. are included:

>>> [imp.name for imp in imports_in_code("def f():\n    import lazily\n")]
['lazily']

Code that doesn’t parse raises a SyntaxError naming the offending file:

>>> list(imports_in_code("import ;", filename="broken.py")
... )
Traceback (most recent call last):
  ...
SyntaxError: invalid syntax (broken.py, line 1)
tec.imports.imports_under_folder(src: ~typing.Any, *, path_filt: ~collections.abc.Callable[[str], bool] | None = None, on_parse_error: ~collections.abc.Callable[[SyntaxError, str], None] = <function warn_of_parse_error>) → Iterator[ImportInfo][source]

Generate the ImportInfo of every .py file under src.

Parameters:

  • src – Anything PyFilesReader accepts: a folder path, a module or package object, or the path of an __init__.py file.

  • path_filt – Optional predicate on the store’s (relative) file paths, to narrow down the files that are parsed. None means “all .py files”.

  • on_parse_error – What to do with a file that doesn’t parse. Called with the SyntaxError and the path. See raise_parse_error(), warn_of_parse_error() (the default) and ignore_parse_error().

Returns:

A generator of ImportInfo.

>>> import tempfile
>>> from pathlib import Path
>>> with tempfile.TemporaryDirectory() as root:
...     _ = Path(root, 'a.py').write_text('import os\n')
...     _ = Path(root, 'b_test.py').write_text('import json\n')
...     all_names = sorted(imp.name for imp in imports_under_folder(root))
...     kept = sorted(
...         imp.name
...         for imp in imports_under_folder(
...             root, path_filt=lambda p: not p.endswith('_test.py')
...         )
...     )
>>> all_names
['json', 'os']
>>> kept
['os']
